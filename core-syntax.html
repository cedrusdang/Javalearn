Java Is Strict by Design, and That Is Its Superpower

Python gives runtime flexibility, JavaScript gives event-driven ubiquity, R gives vectorized data fluency. Java gives explicit models and long-term maintainability through strong types, compile-time guarantees, and powerful runtime tooling.

1.1 Type System Transfer

  • From Python: replace duck typing with interfaces and generics.
  • From JavaScript: replace prototype dynamics with explicit class contracts.
  • From R: represent tabular/data workflows via immutable records and stream pipelines.

Rule for ex-dynamic-language developers: in Java, model your domain first, then implement behavior.

1.2 Core Syntax Patterns

public final class Money {
    private final String currency;
    private final long cents;

    public Money(String currency, long cents) {
        if (currency == null || currency.isBlank()) {
            throw new IllegalArgumentException("currency is required");
        }
        this.currency = currency;
        this.cents = cents;
    }

    public String currency() { return currency; }
    public long cents() { return cents; }

    public Money add(Money other) {
        if (!currency.equals(other.currency)) {
            throw new IllegalArgumentException("Cannot add different currencies");
        }
        return new Money(currency, cents + other.cents);
    }
}

Use immutable value objects for business invariants. This gives safer concurrency, fewer side effects, and easier tests.

1.3 OOP Done Correctly

Principle: Composition over Inheritance

interface PricePolicy {
    long computeFinalCents(long baseCents);
}

final class SeasonalDiscount implements PricePolicy {
    private final int percent;
    SeasonalDiscount(int percent) { this.percent = percent; }

    @Override
    public long computeFinalCents(long baseCents) {
        return baseCents - (baseCents * percent / 100);
    }
}

Instead of subclassing every product type, inject policy strategies. This follows Open/Closed and keeps your codebase flexible.

1.4 Error Handling and API Contracts

  • Use checked exceptions for recoverable boundary operations (IO, network, parsing).
  • Use unchecked exceptions for programming errors or violated invariants.
  • Document thrown exceptions and return semantics in public APIs.
public User loadUser(String id) throws IOException {
    try (var reader = Files.newBufferedReader(Path.of("users.csv"))) {
        return reader.lines()
            .map(this::toUser)
            .filter(u -> u.id().equals(id))
            .findFirst()
            .orElseThrow(() -> new NoSuchElementException("User not found: " + id));
    }
}

1.5 Generics for Real Projects

public interface Repository<ID, T> {
    Optional<T> findById(ID id);
    T save(T entity);
    void deleteById(ID id);
}

Generics enable reusable infrastructure with compile-time safety. For ex-Python/JS developers, this is a major productivity shift once internalized.
