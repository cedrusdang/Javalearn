Bootcamp Setup Standard

This chapter closes the practical gap: exactly what to install, how to configure it, and how to keep environments reproducible across backend, frontend, desktop, and Android tracks.

Philosophy: no "it works on my machine". Every setup step must be scripted, versioned, and documented.

0.5.1 Required Toolchain

  • JDK: use Java 21 LTS minimum, test Java 25 where available.
  • Build: Maven 3.9+ or Gradle 8.7+.
  • IDE: IntelliJ IDEA or VS Code with Java extension pack.
  • Runtime support: Docker, Docker Compose, Git, and a modern shell.
  • Android track: Android Studio, Android SDK Platform, emulator image.

0.5.2 JDK Install Patterns

SDKMAN Strategy (Linux/macOS)

curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install java 21.0.6-tem
sdk install java 25.ea.4-open
sdk default java 21.0.6-tem
java -version

Version Manager Rule

Pin exact versions per repository with .sdkmanrc or .tool-versions.

0.5.3 Maven and Gradle Baselines

Maven pom.xml skeleton

<properties>
  <maven.compiler.release>21</maven.compiler.release>
  <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
</properties>

<build>
  <plugins>
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-compiler-plugin</artifactId>
      <version>3.13.0</version>
      <configuration>
        <release>21</release>
      </configuration>
    </plugin>
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-surefire-plugin</artifactId>
      <version>3.5.2</version>
    </plugin>
  </plugins>
</build>

Gradle build.gradle baseline

plugins {
    id 'java'
}

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}

tasks.withType(Test).configureEach {
    useJUnitPlatform()
}

0.5.4 Project Configuration by Track

Backend (Spring)

Use application.yml with profile overlays: dev, test, prod. Keep secrets in environment variables, not in source.

Frontend (Java UI)

Separate UI routing config, API endpoint config, and security/session config. Make API base URL profile-aware.

Desktop (JavaFX)

Split UI config, service endpoint config, and local cache path config. Support offline mode fallback config.

Mobile (Android Java)

Define build variants (dev/staging/prod), endpoint per flavor, and secure credential storage in Keystore.

0.5.5 Spring Config Example

server:
  port: 8080

spring:
  datasource:
    url: ${DB_URL:jdbc:postgresql://localhost:5432/app}
    username: ${DB_USER:app}
    password: ${DB_PASS:app}

management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus

Use profile files such as application-dev.yml and application-prod.yml for environment-specific values.

0.5.7 Config Governance Rules

  1. Classify every configuration key: secret, runtime, build-time, or feature flag.
  2. Document default value, owner team, and rollback strategy.
  3. Validate mandatory configs at startup and fail fast.
  4. Never mix dev defaults into production images.

0.5.8 Troubleshooting Matrix

  • Build mismatch: check Java toolchain version and compiler release setting.
  • Runtime crash on desktop: verify JavaFX modules and packaging runtime image.
  • Android network failure: inspect flavor endpoint config and TLS certificates.
  • Backend startup fail: check environment variable bindings and database connectivity.
